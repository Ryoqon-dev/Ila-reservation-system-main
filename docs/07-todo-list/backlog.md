## OPS-01 · 실제 환경의 복원 훈련

- **우선순위/상태:** P1 / 운영 확인 필요.
- **근거:** [복호화 도구](../../scripts/restore-backup.mjs), [백업 구현](../../scripts/secure-backup.mjs), [업데이트 검사](../../tests/update.test.mjs), 기존 REVIEW의 실제 DB 복구 훈련 미수행 기록.
- **현재 구현:** 암호화 DB/별도 키 백업 및 새 recovered 폴더 복호화가 있습니다. 복호화 성공만으로 원격 DB 복원 성공을 증명하지 않습니다.
- **관련 Issue/PR:** 출처 #1, 후속 미등록.
- **완료 조건:** 운영 담당자가 승인한 격리 환경에서 DB·설정·키 복구 후 데이터 건수/관계/예약 확인코드·권한 동작을 비교하고 복구 시간과 실패 대응을 기록합니다. 실제 운영 DB에 자동 덮어쓰지 않습니다.

## SEC-01 · 비밀번호 KDF 강화 가능성 검증

- **우선순위/상태:** P1 / 조사 필요.
- **근거:** [passwordHash](../../lib/security.mjs), [관리자 인증](../../lib/admin-auth.mjs), [보안 검사](../../tests/security-hardening.test.mjs), 기존 REVIEW의 PBKDF2 작업량 한계.
- **현재 구현:** PBKDF2-SHA256 100,000회와 서버 pepper를 사용합니다. 문서에서 현재 정책을 더 강한 방식으로 바꾸어 서술하지 않습니다.
- **관련 Issue/PR:** 출처 #1, 후속 미등록.
- **완료 조건:** 현재 플랫폼 WebCrypto/CPU 제약을 실제 환경에서 확인하고 대안의 성능·기존 비밀번호 호환·단계적 전환·실패 복구를 검증한 설계와 회귀 검사를 별도 PR로 제출합니다.

## OPS-02 · 플랫폼 MFA·개인정보 보관·인수인계 확인

- **우선순위/상태:** P1 / 운영 확인 필요.
- **근거:** [개인정보](../../lib/privacy.mjs), [자료 관리](../../lib/data-management.mjs), [자료 검사](../../tests/data-management.test.mjs), 기존 REVIEW의 플랫폼 계정/과거 사본/보관 정책 한계.
- **현재 구현:** 앱 MFA·암호화·자료 정리는 있습니다. Cloudflare 계정 MFA, 이미 복사한 백업, 플랫폼 복원 지점, 오프라인 키 보관은 앱이 일괄 관리하지 않습니다.
- **관련 Issue/PR:** 출처 #1, 후속 미등록.
- **완료 조건:** 담당자가 플랫폼 MFA와 접근자를 확인하고, 학기별 개인정보/백업 보관·삭제 기준 및 키/백업 분리 보관·퇴임 시 권한 회수 기록을 남깁니다. 비밀값은 Git에 기록하지 않습니다.

## QA-01 · 실제 PC·휴대전화·운영 부하 확인

- **우선순위/상태:** P1 / 운영 확인 필요.
- **근거:** [UI 정적 검사](../../tests/ui-check.mjs), [런타임 검사](../../scripts/runtime-check.mjs), [사용량](../../lib/data-metrics.mjs), 기존 REVIEW의 실제 기기/무료 계정 CPU 검증 한계.
- **현재 구현:** 자동·정적·로컬 Worker 검사가 있고 과거 브라우저 크기별 검증 기록도 있습니다. 실제 휴대전화·사용자 PC·운영 부하를 모두 검증했다는 뜻은 아닙니다.
- **관련 Issue/PR:** 출처 #1, 후속 미등록.
- **완료 조건:** 승인된 테스트 계정·가상 예약으로 가입/승인/대여 입장/예약/취소/관리자 MFA/조회 링크/PNG를 실제 지원 기기에서 확인합니다. 운영 담당자가 허용한 부하 범위에서 Worker CPU·D1·요청 지표를 측정하고 결과와 조건을 기록합니다.
