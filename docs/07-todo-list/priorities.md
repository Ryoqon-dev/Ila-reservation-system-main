# 우선순위와 상태 기준

| 우선순위 | 기준 | 처리 방향 |
|---|---|---|
| P0 | 확인된 현재 데이터 손실·권한 우회·운영 중단 | 재현과 영향 증거를 먼저 기록하고 즉시 대응 |
| P1 | 운영 인수인계·개인정보 보호에 필요한 검증 또는 강화 | 담당자·환경·수락 기준을 정해 별도 변경 |
| P2 | 사용성·유지보수 개선 또는 추가 인증 수단 | 제품 필요성과 구현 범위를 확인 후 계획 |

상태는 `미착수`, `조사 필요`, `운영 확인 필요`, `진행 중`, `완료`를 사용합니다. 증거가 없는 의심을 P0 취약점으로 단정하지 않습니다. 이번 조사에서 신규로 재현된 P0 장애는 등록하지 않았습니다.

## 항목 작성 규칙

모든 항목은 ID, 우선순위, 상태, 근거 코드·테스트·기록, 관련 Issue/PR, 완료 조건을 갖춥니다. 개별 후속 이슈가 없으면 `미등록`으로 명시하고 출처인 [Issue #1](https://github.com/gu2417/Ila-reservation-system/issues/1)과 연결합니다. 원래 이슈의 완료가 별도 후속 작업의 완료를 뜻하지 않습니다.

완료 상태로 바꾸려면 검증 일시·환경·명령/결과와 변경 PR을 기록합니다. 보안 정책 변경은 호환성·성능·기존 계정 영향도 함께 확인합니다. 과거 REVIEW의 통과 건수·audit 결과를 현재 검사 결과로 사용하지 않습니다.

## 문서 갱신

기능이 바뀌면 해당 분야의 현행 문서를 수정하고, 배포 시점의 검사 기록은 `review-history/`에 추가합니다. 반복되는 상세 설명은 기준 문서 하나에 두고 상대 링크로 연결합니다. 문서 이동 시 [이전 규칙](../04-file-structure/document-migration.md)을 적용합니다.
