# 1.10.0 예약 조회 권한·시간표 설계

설계일: 2026-11-02(한국시간). 기능 구현 전에 기존 1.9.1 소스와 예약·인증 경로를 확인한 뒤 작성했습니다. 범위는 사용자의 최종 요구사항 1~6입니다. 운영 DB에는 접근하지 않습니다.

## 권한과 개인정보

| 기능 | 메인 관리자 | 조회 전용 서브 관리자 | 만료 링크 |
|---|---|---|---|
| 인증 | 기존 비밀번호+2차 인증 | 별도 아이디·비밀번호, 2차 인증 없음 | 발급받은 링크로 제한된 조회 세션 |
| 예약 목록 | 기존 전체 메뉴 | 예약 목록만 | 발급 시 지정한 날짜·장소의 목록만 |
| 개인정보 | 신청자 이름·전체 전화번호 등 기존 관리 정보 | 응답 자체에서 제외 | 응답 자체에서 제외 |
| 예약·사진·벌점·계정 수정, CSV | 기존 권한 유지 | 금지 | 금지 |
| 예약 시간표 | 이용 가능 | 이용 가능 | 허용된 날짜·장소만 |
| 계정·링크 발급 | 메인만, 현재 비밀번호+새 2차 인증으로 확인 | 금지 | 금지 |

조회 전용 응답은 동아리명·날짜·장소·시작/종료·상태만 명시적으로 선택합니다. 전화번호·대표자·메모·사유·방 비밀번호·학번·예약 확인코드·다른 관리 정보는 조회 전용 SQL과 응답에 포함하지 않습니다. 클라이언트의 role/admin 플래그를 신뢰하지 않습니다. 기존 메인 MFA 쿠키와 별도의 쿠키·DB 테이블을 사용하여 권한을 격리합니다.

## 데이터 보존·DB

추가 마이그레이션 0012만 제공합니다. 기존 테이블의 행·상태·암호화 값을 초기화하지 않습니다.

- reservation_readers: 아이디, 표시 이름, salt, 서버 pepper를 적용한 비밀번호 해시, 활성 상태, 버전, 생성/수정 시각.
- reservation_reader_sessions: 해시된 불투명 세션, 계정 참조, 절대 만료와 마지막 조작 시각. 15분 미사용·최대 8시간, 계정 변경·중지 시 기존 세션 회수.
- reservation_share_links: 링크 토큰의 해시, 이름, 고정 조회 시작/끝 날짜, 허용 장소, 만료 시각, 정지 상태, 발급 시각. 조회 범위 최대 7일, 링크 유효 기간 최대 7일, 기본 24시간.
- reservation_share_sessions: 링크별 해시된 세션, 만료 시각. 모든 데이터 요청에서 원 링크의 만료·정지·범위를 재확인.

토큰·세션 원문을 DB·운영 기록에 저장하지 않습니다. 주요 조건과 FK에 인덱스를 둡니다. 기존 업데이트 도구의 암호화 백업·보안 키와 DB ID·공개 범위 보존 절차를 유지합니다.

## 진입·만료 링크

메인 관리자 로그인 화면에 조회 전용 로그인 선택지를 추가합니다. 서브 관리자 로그인 후에는 예약 목록 전용 화면으로 이동합니다. 동일 브라우저의 기존 메인 세션은 해제하여 남아 있는 메인 권한을 공유하지 않습니다. 메인 메뉴·예약 변경 API는 권한을 주지 않습니다.

링크는 URL fragment에 256비트 무작위 토큰을 담습니다. 페이지 진입 시 주소에서 토큰을 제거하고, 동일 출처 POST로 제한 세션을 발급받습니다. 이후 요청은 HttpOnly·Secure·SameSite 쿠키를 사용합니다. 토큰을 GET 쿼리나 접근 기록에 노출하지 않습니다. 링크는 만료 전 여러 번 사용 가능하며, 소지자가 전달하면 다른 사람도 쓸 수 있음을 발급 UI에 설명합니다. 링크 생성·정지·계정 저장은 메인 관리자 권한을 DB 실행 시점에도 확인합니다.

메인만 계정 생성·수정·사용 중지와 링크 발급·정지를 수행합니다. 현재 비밀번호와 새 인증 코드가 필요한 발급·계정 변경은 기존 재인증 절차를 재사용합니다. 비밀번호·토큰 추측에는 요청 제한을 적용합니다. 로그인·교환 시 만료 세션을 정리합니다.

## 예약 목록과 시간표

기존 예약 목록 아래에 기본 접힘 상태의 ‘예약 시간표’를 추가합니다. 시간표의 날짜는 서버 한국시간 기준 당일로 시작하며, 목록의 기간/검색/정렬 필터와 별도로 해당 날짜 전체를 조회합니다. 조회 링크에서는 허용 범위 안에서만 선택합니다. 메인·서브·링크가 같은 시간표 컴포넌트와 최소 응답 API를 사용합니다.

09:00~21:00 세로 시간축, 심정실·진리실·창의실 가로 열에 실제 시작/종료 시간 길이대로 예약 블록을 배치합니다. 확정·추가승인만 표시하고 취소·삭제는 제외합니다. 블록 안에는 동아리명만 표시합니다. 긴 이름은 줄바꿈하고 빈 날짜는 빈 표를 보여줍니다. 모바일에서는 시간축과 장소 제목을 읽을 수 있게 표 영역을 구성합니다. 이미지는 브라우저에서 동아리명만 담은 PNG로 생성하며 외부 이미지 서비스나 유료 API를 사용하지 않습니다.

메인 예약 목록에서는 기존 마스킹 처리를 제거하되 MFA 세션을 재확인한 후 전체 전화번호를 반환합니다. 새 조회 전용 API에 이 경로를 공유하지 않습니다.

## 상단 남은 로그인 시간

메인 관리자의 ‘관리자’ 메뉴 오른쪽에 남은 분·초를 표시합니다. 서버에서 받은 idleExpiresAt(15분)과 절대 만료 중 이른 시각을 사용합니다. 실제 관리자 조작에 따른 갱신과 다른 탭 활동을 화면에 반영합니다. 카운트다운·자동 조회는 시간을 연장하지 않습니다. 기기 시계 변경과 무관한 기존 서버 시계 동기화를 재사용하고, 만료/로그아웃 시 표시와 개인정보 화면을 해제합니다.

## 검증 계획

1. 기본 기존 예약·계정·벌점·암호화·오픈·취소·CSV·업데이트 회귀 검사.
2. 메인만 전체 전화번호를 수신하고 서브/링크/비회원에게 민감 필드가 없는지 검사.
3. 모든 기존 수정·관리·내보내기 API에 서브/링크 쿠키·role 위조·잘못된 메서드로 접근하여 거부 확인.
4. 로그인 실패·만료·중지·비밀번호 변경·권한 회수·CSRF·다른 쿠키로 권한 대체·동시 수정/저장 실패 검사.
5. 링크 만료 정각·날짜/장소 범위 조작·정지·기존 세션 회수·토큰 미저장·추측 방지·동시 로그인 경로 검사.
6. 시간표 정확한 길이·취소 제외·부분 시간·이름 이스케이프·빈 날짜·날짜 변경·PNG의 개인정보 제외 검사.
7. 카운트다운의 갱신·다른 탭 반영·만료·잘못된 기기 시계·자동 조회의 비갱신 확인.
8. 로컬 Worker+D1, PC와 모바일 크기 브라우저 검증. 운영 서버·실제 휴대전화·부하 검사는 수행한 것으로 표현하지 않음.

참고: OWASP Authorization / Session Management Cheat Sheets의 기본 거부, 요청별 권한 확인, URL·로그의 인증정보 노출 방지 원칙을 반영합니다.
