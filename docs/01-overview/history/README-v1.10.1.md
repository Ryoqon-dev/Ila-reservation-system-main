# 일아 동아리 통합 관리 시스템 1.10.1

## GitHub 소스 저장소

이 저장소는 사이트의 **소스 코드 보관용**입니다. 운영 서버 설정(`wrangler.json`), 보안 키(`.secrets/`), 실제 데이터와 백업은 포함하지 않습니다. 의존성과 빌드 결과물은 아래 명령으로 로컬에서 준비합니다(Node.js 22.13 이상).

```sh
npm ci
npm run check
npm test
npm run build
```

GitHub에 올리는 것만으로 기존 Cloudflare 운영 사이트가 배포되지는 않습니다. 운영 사이트 업데이트는 기존 배포 폴더의 설정을 유지하고, 빌드 결과(`dist/`)가 포함된 별도 배포 ZIP의 적용 절차를 따르세요.

**이번 적용 안내: [READ_ACCESS_UPDATE.md](../../02-features/history/READ_ACCESS_UPDATE.md).** 예약 조회 링크의 만료 시각을 한국시간 기준으로 발급 후 최대 365일까지 지정할 수 있습니다. 예약 조회 날짜 범위는 최대 7일로 유지됩니다. 1.10.0을 사용 중이라면 DB 구조 변경이 없습니다. 예약 조회 전용 서브 관리자, 예약 시간표와 동아리명 전용 PNG, 메인 관리자 전체 전화번호 표시와 남은 로그인 시간도 그대로 제공됩니다.

사진 제출 상태를 한 버튼으로 통합하고, 관리자 로그인 만료를 **15분 미사용**으로 변경했습니다. 기존 예약·계정·사진 확인 기록·벌점을 유지합니다. **이번 적용 안내는 [PHOTO_SESSION_UPDATE.md](../../02-features/history/PHOTO_SESSION_UPDATE.md)**를 읽어주세요. 1.9.0에서 업데이트하면 DB 구조 변경이 없습니다. 한국시간 자동 오픈과 이전 보안 업데이트도 포함된 누적본입니다.

## 무료 독립 호스팅 안내

기존 비공개 Sites 버전의 화면·예약 규칙·동아리/벌점 관리 기능을 Cloudflare Workers Free + D1으로 운영할 수 있도록 준비한 별도 배포본입니다. 기존 사이트의 공개 설정과 운영 데이터는 변경하지 않았습니다. 이 파일만으로 외부 서버에 배포가 완료된 것은 아닙니다.

## 기존 운영 사이트 업데이트

2026-11-06 조회 링크 만료 기간 업데이트(1.10.1)입니다. **[READ_ACCESS_UPDATE.md](../../02-features/history/READ_ACCESS_UPDATE.md)를 읽고 새로 압축 해제한 폴더의 `APPLY_SITE_UPDATE.cmd`를 실행하세요.** 기존 DB 암호화 백업 → 소스 보관·교체 → 미적용 마이그레이션 확인 → 같은 주소 배포 순서로 진행합니다. 기존 예약·계정·동아리 정보·벌점·자동 오픈·사진 상태와 15분 미사용 정책을 유지합니다. 신규 DB 생성이나 초기 설정 명령을 다시 실행하지 않습니다. 아래의 신규 설치 절차는 처음 서버를 만들 때만 사용합니다.

## 비용을 0원으로 유지하는 구성

- Cloudflare **Workers Free** 계정과 D1 무료 사용량만 사용합니다.
- 별도 도메인 구매 없이 Cloudflare의 기본 `workers.dev` 주소를 사용합니다. 계정 설정 이후 실제 주소가 결정됩니다.
- 유료 Workers, 유료 도메인, 문자 인증, R2 사진 저장 서비스를 신청하지 않습니다. 사이트 설정 이미지 3개는 크기를 제한해 D1에 보관합니다.
- 입실/퇴실 사진은 기존 지원부 오픈채팅으로 보내고 관리자만 제출 상태를 기록합니다.
- 무료 서버 요청 한도는 계정 전체 하루 100,000회이며, 한도를 넘으면 일시적으로 요청이 실패할 수 있습니다. 무제한 이용을 의미하지 않습니다.
- 화면·사진·JS·CSS는 정적 자산으로 제공하고 서버는 예약 API를 처리합니다. 공개 모드의 정적 자산 요청은 무료입니다. 비공개 테스트에서는 비밀번호 확인을 위해 정적 자산도 서버를 경유합니다.
- D1 무료 제공량: 하루 읽기 500만 행, 쓰기 10만 행, 계정 총 저장 공간 5GB. Workers Free는 요청당 CPU 10ms 제한도 있습니다. 로컬 테스트로 실제 Cloudflare의 CPU 제한 충족을 확정할 수는 없으므로 무료 계정의 비공개 테스트에서 최종 확인해야 합니다.
- 유료 업그레이드는 이 코드에 포함되지 않습니다. 사용하는 계정에 이미 유료 구독이 있다면 별도로 확인하세요.

확인한 공식 안내 (2026-10-14):
https://developers.cloudflare.com/workers/platform/pricing/
https://developers.cloudflare.com/workers/platform/limits/
https://developers.cloudflare.com/d1/platform/pricing/
https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/

## 배포 도구 보안

이번 ZIP은 Vite 8.3.4, Wrangler 4.152.0과 undici 7.30.1을 의존성 잠금 파일에 고정했습니다. 2026-10-30 검사에서 개발 도구를 포함한 npm audit 결과는 취약점 0건입니다. 새 보안 공지는 이후 달라질 수 있습니다.

기존 운영 사이트에는 위 업데이트 도구를 사용하세요. 도구가 `npm ci`로 잠금 파일에 맞춰 설치합니다. `npm audit fix --force`로 의존성을 임의 변경할 필요는 없습니다.

## 1. 무료 계정 만들기

1. https://dash.cloudflare.com/sign-up 에서 이메일로 계정을 만들고 이메일 인증을 완료합니다.
2. 가능하면 총동아리연합회가 인수인계할 수 있는 이메일을 사용합니다. 비밀번호를 채팅에 보내지 마세요.
3. **Workers Free**를 유지합니다. 도메인 구매나 사이트의 DNS 등록은 이 방식에 필요하지 않습니다.
4. 기본 `workers.dev` 주소를 아직 만들지 않았다면 Workers & Pages 영역에서 계정용 하위 주소를 설정합니다.

## 2. PC에서 준비

1. Node.js 22.13 이상(또는 지원되는 최신 LTS)을 설치합니다. https://nodejs.org/
2. ZIP을 압축 해제합니다.
3. 파일 탐색기에서 `ila-free-hosting` 폴더를 열고 터미널을 엽니다. `package.json`이 보이는 폴더입니다.
4. 아래 명령을 하나씩 실행합니다.

```sh
npm install
npm run check
npm test
npm audit
```

ZIP에는 빌드된 `dist`도 들어 있습니다. 화면을 수정한 경우에만 `npm run build`로 다시 빌드하세요.

## 3. 외부에 공개하지 않고 서버 준비

```sh
npm run prepare:hosting
```

- 브라우저가 열리면 본인의 Cloudflare 계정으로 로그인하고 Wrangler 연결을 승인합니다. 비밀번호나 API 토큰을 다른 사람에게 전달할 필요가 없습니다.
- 전용 D1 데이터베이스, 테이블, 서버 보안 키를 만들고 서버를 배포합니다.
- **기본 주소와 미리보기 주소는 모두 비활성화**됩니다. 이 단계에서는 누구나 접속하는 공개 사이트가 생기지 않습니다.
- `.secrets/runtime.json`과 `.secrets/setup-info.txt`가 로컬에 생성됩니다. 이 파일은 ZIP 원본에 포함되지 않으며 외부 공유·Git 업로드를 하면 안 됩니다.
- 중단됐다면 같은 폴더에서 다시 실행할 수 있습니다. 기존 키와 DB ID를 유지합니다. D1 생성 직후 중단되어 DB ID가 저장되지 않았다면 Cloudflare D1의 기존 `ila-club-db` ID를 확인해 `wrangler.json`에 입력합니다. 같은 DB를 중복 생성하지 마세요.
- DB가 이미 있다며 실패하면 기존 DB ID를 `wrangler.example.json`의 `database_id`에 입력해 `wrangler.json`으로 저장한 다음 재실행합니다.

## 4. 비공개 테스트 주소 열기

```sh
npm run publish:private
```

명령 마지막에 실제 URL이 표시됩니다. 이 주소는 별도의 접속 비밀번호로 보호됩니다. `.secrets/setup-info.txt`에 적힌 **접속 아이디 `ila-owner`와 접속 비밀번호**를 입력합니다. ChatGPT 로그인은 필요하지 않습니다. 테스트 주소와 비밀번호를 외부에 배포하지 마세요.

1. 첫 화면 → 관리자 → `.secrets/setup-info.txt`의 최초 설정 키 입력.
2. 사용할 관리자 아이디(영문·숫자 등 4~40자)와 관리자 비밀번호(10자 이상)를 생성합니다.
3. 현 동아리 관리 → 동아리 이름·방 호수·방 비밀번호 등록.
4. 장소대여 관리 → 날짜와 심정실·진리실·창의실 선택 → 예약 오픈.
5. 현 동아리 관리에서 대표 계정을 발급하거나 대표자의 가입 신청을 승인합니다. 일반 사용자 메뉴에서 승인된 계정으로 로그인 → 날짜·장소·시간 선택 → 대표자·전화번호 입력 → 동의 후 예약합니다. 동아리 이름은 자동 입력됩니다.
6. 예약 성공 화면에서 날짜·장소·시간을 확인합니다. 로그인 후 **우리 동아리 예약**에서 조회·취소할 수 있습니다. 별도의 확인서 다운로드나 예약코드 입력은 필요하지 않습니다.
7. 관리자 → 예약 내역·입퇴실 사진 상태·점검 벌점 확인.

모바일과 PC 모두에서 다음을 확인하세요: 초기 공지 닫기, 날짜/장소/시간 선택, 여러 날짜 오픈, 같은 시간 중복 예약 거절, 우리 동아리 예약 조회/취소, 관리자 로그아웃 후 권한 차단, 방 비밀번호 조회, 벌점 등록/취소/통계.

무료 계정에서 오류 1102(CPU 제한)나 1027(하루 요청 한도)가 나오면 유료로 전환하지 말고 로그와 실패한 동작을 확인해 개선해야 합니다. 서버의 비밀번호 해시 강도를 낮춰 무료 한도를 맞추지 않습니다.

## 5. 외부 공개 — 사용자 승인 후에만

신규 사이트를 외부 공개할 때는 운영자의 승인과 테스트를 완료한 뒤 아래 명령을 직접 실행합니다. 이미 운영 중인 사이트의 계정 업데이트에는 공개 전환 명령을 다시 실행하지 않습니다.

```sh
npm run publish:public -- --approved
```

이 명령은 테스트 접속 비밀번호를 제거하고 링크를 가진 누구나 접속하도록 배포합니다. 관리자·동아리 로그인, 동아리별 예약 권한, 비밀번호 암호화는 유지됩니다. 공개 페이지의 정적 자산은 서버 실행을 우회해 비용과 CPU 사용을 줄입니다.

다시 테스트용 비공개 상태로 돌리려면 `npm run publish:private`를 실행합니다. 주소는 유지되고 접속 비밀번호가 다시 필요해집니다.

## 운영과 인수인계

- 예약은 모든 날짜·장소가 기본 마감입니다. 관리자만 날짜를 열 수 있습니다.
- 심정실·진리실·창의실, A 15~17시/B 17~19시/C 19~21시, 오전 한 시간 단위, 금·주말·휴일 총 4시간 규칙이 유지됩니다.
- 예약 확인은 로그인한 동아리의 예약 내역에서 제공합니다. 문자 발송 기능은 사용하지 않습니다.
- JSON/SQL 데이터를 포함한 기존 구글 시트와 Sites 데이터는 자동으로 옮겨지지 않습니다. 실제 데이터가 있다면 기존 예약이 새 DB로 이관되기 전까지 두 주소에서 동시에 예약을 받지 마세요. 암호화된 방 비밀번호를 이관하려면 기존 암호화 키도 필요합니다.
- 이 준비본은 실제 동아리 목록·전화번호·비밀번호·Cloudflare 계정 정보를 포함하지 않습니다.
- 최초 설정 키는 관리자 생성에만 사용됩니다. 생성 후 다시 관리자 계정을 만들 수 없습니다.
- 공개 후 관리자 계정 변경은 기존 관리자 세션을 만료시킵니다.
- 서버 요금제와 사용량을 Cloudflare 대시보드에서 확인합니다. 무료 한도 초과 시 일부 동작이 중단될 수 있습니다.

백업 명령:

```sh
npm run backup
```

`backups` 폴더에 DB SQL과 암호화 키가 함께 저장됩니다. 개인정보가 있는 파일이므로 안전하게 보관합니다. `ROOM_KEY`를 잃으면 방·계정 비밀번호를 복원할 수 없고, `BOOKING_KEY`를 바꾸면 기존 동아리 로그인 검증과 예약 확인코드 재발급이 동작하지 않을 수 있습니다. 두 키를 임의로 변경하지 마세요. 다음 지원부장에게 계정 접근 권한·관리자 계정·코드·백업·키를 안전하게 인수인계하세요.
