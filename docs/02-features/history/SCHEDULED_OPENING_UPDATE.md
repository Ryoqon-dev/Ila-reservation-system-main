# 1.9.0 한국시간 자동 오픈 업데이트

기존 예약 목록을 보존하면서, 지정한 날짜·장소의 예약 접수를 한국시간의 원하는 시각에 시작합니다. 예: **10월 30일 13:00:00에 11월 1~30일 심정실·진리실 예약 접수 시작**.

## 기존 예약 보존

- 이번 추가 DB 변경(0011)은 자동 오픈 설정용 테이블 2개와 인덱스만 만듭니다. 기존 예약·확인코드·동아리·계정·벌점·기존 오픈 상태를 삭제하거나 초기화하지 않습니다.
- 기존 예약이 있는 날짜에 자동 오픈을 설정·취소해도 해당 대여 예약은 유지됩니다. 기존 예약 시간은 계속 중복 예약할 수 없습니다.
- 이미 오픈된 날짜·장소 또는 자동 오픈이 설정된 대상과 겹치면 저장을 거부합니다. 대상 일부만 몰래 변경하지 않고 일괄 설정 전체를 거부합니다. 대상을 나누거나 대기 중인 설정을 취소한 뒤 새로 지정하세요.
- ‘자동 오픈 취소’는 오픈 시각 전의 설정만 취소합니다. 기존 대여 예약을 취소하는 기능과 별개입니다.
- ‘지금 오픈·마감’으로 선택한 날짜·장소를 직접 변경하면 그 대상의 자동 오픈 설정은 해제됩니다. 다른 대상은 유지합니다. 활성 예약이 있으면 기존처럼 일괄 마감 전체를 거부합니다.

## 적용 방법

1. ZIP을 **기존 배포 폴더와 다른 폴더**에 압축 해제합니다.
2. 새 폴더의 `APPLY_SITE_UPDATE.cmd`를 실행합니다.
3. 기존에 실제로 배포한 `wrangler.json`과 `.secrets/runtime.json`이 있는 폴더 경로를 입력합니다. 새 DB 생성·초기 설정 명령은 필요하지 않습니다.
4. 서로 다른 DB 백업 암호와 키 보관용 암호를 각각 입력합니다. 기존 1.8.0처럼 DB를 암호화 백업한 뒤 파일을 교체하고, 기존 DB에 추가 테이블을 준비해 같은 Worker에 배포합니다. 기존 DB ID·보안 키·공개/비공개 설정을 유지합니다. 백업에 실패하면 소스 교체·DB 변경 전 중단합니다.
5. 완료 후 사이트를 새로고침하고 관리자 메뉴에서 설정합니다. 1.8.0 보안 업데이트를 아직 적용하지 않았다면 누적 보안 전환·최초 인증앱 등록이 함께 필요합니다. 자세한 내용은 SECURITY_UPDATE.md에 있습니다.

## 관리자 사용법

1. **관리자 → 장소대여 시스템 관리 → 예약 오픈**으로 이동합니다.
2. **시간 지정 자동 오픈**을 선택합니다.
3. 대여 시작·종료 날짜와 필요 시 추가 날짜, 심정실·진리실·창의실 중 대상 장소를 고릅니다. 한 번에 최대 93일·3개 장소를 선택합니다.
4. **오픈 날짜(한국시간)**와 **시·분·초**를 지정하고 **자동 오픈 설정**을 누릅니다. 오픈 시각은 현재 서버 시각 이후, 첫 대여 대상 날짜 또는 그 이전이어야 합니다.
5. 아래 **자동 오픈 설정 목록 → 오픈 대기**에서 내용과 전체 날짜·장소를 확인할 수 있습니다. 오픈 시각이 지나면 **오픈 완료**에서 확인합니다. 목록은 30건씩 조회합니다.
6. 변경하려면 오픈 시각 전에 **자동 오픈 취소** 후 새로 설정하세요. 이미 오픈된 날짜를 닫을 때는 **지금 오픈·마감**을 사용하세요. 기존 활성 예약은 보호됩니다.

## 사용자 화면과 시간 기준

- 날짜와 현재 시각은 서버 시간을 한국시간(Asia/Seoul, UTC+9)으로 표시합니다. 접속 기기의 시계 변경으로 예약을 앞당길 수 없습니다.
- 선택한 날짜·장소에 예정된 오픈이 있으면 예정 시각과 남은 시간이 표시됩니다. 서버에서 받은 시각과 브라우저의 경과 시간을 사용해 표시하므로, 기기의 시계를 바꿔도 시간 계산에 사용하지 않습니다.
- 예정된 오픈을 확인한 화면은 열린 상태에서 자동으로 최신 시간표를 확인합니다. 탭을 다시 보거나 새로고침해도 확인합니다. 다른 관리자가 새 설정을 추가한 직후에는 시간표 새로고침으로 확인할 수 있습니다.
- 실제 접수 허용 여부는 예약을 저장하는 서버·DB에서 결정합니다. 설정한 초가 되기 전에는 거부하고 그 시각부터 허용합니다. 관리자의 PC나 브라우저가 켜져 있을 필요가 없습니다. 별도의 주기 실행 작업이나 외부 시각 서비스는 추가하지 않습니다.
- 화면 갱신은 네트워크와 브라우저 상태에 따라 조금 늦게 보일 수 있습니다. 인터넷이 끊겼을 때 화면 표시만으로 예약이 확정되지는 않습니다.
- 기존 로그인·2차 인증·관리자 15분 미사용 만료·장소대여 1인 입장·중복 예약/시간 제한·취소·추가승인·벌점·사이트 설정·저작권 표기는 유지합니다.

## 검증

기존 데이터가 있는 테스트 DB에서 추가 테이블 준비 전후의 모든 기존 예약 값·상태·확인코드·계정·벌점 데이터를 비교합니다. 오픈 직전/정각, 조기 요청, 동일 요청 재시도, 동시 관리자 충돌, 취소와 수동 오픈·마감, 관리자 권한 회수·저장 실패를 검사합니다. 실제 Workers·D1 로컬 런타임에서 자동 오픈 후 새 예약이 가능하며 기존 예약이 유지되는지 확인합니다. 운영 Cloudflare 계정과 실제 DB에는 접근하지 않았으므로, 실제 반영은 위 적용 절차를 실행해야 합니다.
