# 일아 동아리 대표 계정 업데이트 — 사용·적용 안내

현재 ZIP은 대표 계정 기능과 사이트 설정을 함께 포함합니다. **최신 운영 적용 방법은 SITE_SETTINGS_UPDATE.md와 APPLY_SITE_UPDATE.cmd를 사용하세요.** 아래 계정 기능·사용법은 유지됩니다.

대상 사이트: https://ila-club-management.sunmoonclubunion.workers.dev

이 파일은 운영 사이트에 적용할 수정본입니다. 다운로드만으로 운영 사이트가 변경되지는 않습니다. 기존 Cloudflare 계정, 사이트 주소, D1 데이터, 관리자 계정, 보안 키, 공개/비공개 설정을 유지합니다. Supabase나 Vercel 가입, 유료 서비스 신청은 필요하지 않습니다.

## 1. 기존 운영 사이트에 적용하기

1. 새 ZIP을 다운로드하고 **기존 배포 폴더와 다른 새 폴더**에 압축을 풉니다. 바탕화면에 `일아_계정업데이트` 폴더를 만들면 구분하기 쉽습니다. 기존 운영 폴더를 삭제하거나 통째로 덮어쓰지 마세요.
2. 새 폴더 안 `ila-free-hosting`을 열고 `APPLY_ACCOUNT_UPDATE.cmd`를 더블클릭합니다. 확장자가 숨겨져 있으면 `APPLY_ACCOUNT_UPDATE`로 보입니다.
3. ‘기존 배포 폴더 경로를 붙여넣고 Enter를 누르세요’가 나오면 **예전에 배포에 사용했던 폴더 경로**를 입력합니다. 현재 확인된 경로는 다음입니다.

```text
C:\Users\김주영\Desktop\36대 총동 파일\ILA_Free_Hosting\ila-free-hosting
```

4. 도구가 순서대로 ① 기존 운영 DB와 보안 키 백업 ② 기존 소스 백업과 수정본 복사 ③ 계정 테이블 추가 ④ 동일 사이트 재배포를 실행합니다. 계정 테이블 추가 과정에서 계속할지 물으면 `y`를 입력하고 Enter를 누르세요.
5. **‘사이트 설정 업데이트 및 배포 완료’**가 표시될 때까지 창을 닫지 마세요. 성공 후 아무 키나 눌러 닫습니다.
6. 기존 사이트를 열고 PC에서는 `Ctrl + F5`, 모바일에서는 새 시크릿 탭으로 접속합니다.

이번 파일에는 미리 빌드된 화면이 있습니다. 기존 폴더에 설치한 Wrangler를 사용하므로 `npm install`, `npm run build`, `prepare:hosting`, 공개 전환 명령을 다시 실행할 필요가 없습니다. 새 DB와 새 암호화 키도 만들지 않습니다.

폴더를 옮겼다면 기존 `wrangler.json`, `.secrets`, `node_modules`가 있는 폴더를 탐색기로 열고 주소창에서 경로를 복사하세요. 새 ZIP 폴더 자체에는 운영 설정과 키가 없으므로 입력할 대상이 아닙니다.

명령 오류가 있으면 창의 오류 문구를 확인합니다. Cloudflare 로그인 만료라면 **기존 배포 폴더**에서 `npx wrangler login`을 실행한 후 업데이트를 다시 실행할 수 있습니다. 오류 화면만 전달하고, 비밀번호·키·DB 백업은 채팅에 보내지 마세요.

백업은 기존 폴더의 `backups/account-update-날짜...`에 있습니다. `data/database.sql`, `data/runtime.json`, `data/wrangler.json`과 교체 전 소스가 보관됩니다. 개인정보와 키가 있으므로 외부에 업로드하지 마세요. DB 테이블 변경은 0003 마이그레이션의 추가 작업뿐이며 기존 예약·동아리·벌점 테이블을 초기화하지 않습니다. 중간에 실패했다면 같은 수정본으로 다시 실행할 수 있습니다. 실패한 마이그레이션은 Wrangler가 되돌리며, 이미 적용된 것은 재실행하지 않습니다.

## 2. 관리자 사용 순서

1. 기존 관리자 아이디·비밀번호로 로그인합니다.
2. **현 동아리 관리**에서 기존 동아리 이름과 방 호수를 확인합니다. 새 동아리는 먼저 등록합니다.
3. 아래 두 방식 중 하나로 대표 계정을 준비합니다.
   - **대표자가 신청:** 일반 동아리 사용자 → 회원가입 → 소속 동아리·아이디·비밀번호 입력. 관리자는 현 동아리 목록에서 ‘승인 대기’ 계정을 확인하고 대표자와 소속을 별도로 확인한 뒤 **가입 승인**을 누릅니다.
   - **관리자가 발급:** 해당 동아리의 **계정 추가** → 아이디·비밀번호 입력 → ‘정식 회원’을 선택하고 저장합니다. 해당 대표자에게 정보를 안전하게 전달합니다.
4. 동아리 목록에는 이름, 방 호수, 방 비밀번호 항목, 계정 아이디, 계정 비밀번호 항목이 표시됩니다. 비밀번호는 기본적으로 가려집니다. 대표 계정 비밀번호를 확인하려면 **확인 → 관리자 비밀번호 재입력**이 필요합니다. 확인 사실만 처리 기록에 남기며 비밀번호 자체는 기록하지 않습니다.
5. **계정 수정**에서 아이디·비밀번호·회원 상태를 변경할 수 있습니다. 새 비밀번호를 비워두면 기존 비밀번호가 유지됩니다. **계정 정지**는 계정을 유지한 채 이용을 차단하고, **계정 삭제**는 대표 계정만 제거합니다. 기존 예약·벌점은 삭제하지 않습니다.

동아리당 계정 1개이며 50개로 제한하지 않았습니다. 60개 계정 생성과 서로 다른 동아리의 독립 로그인을 자동 검증했습니다. 단, 실제 서비스 전체에는 Cloudflare 무료 사용량 제한이 적용됩니다.

이미 가입 신청된 동아리는 회원가입 목록에서 빠집니다. 잘못된 선점 신청이면 관리자가 신청자를 확인해 계정을 삭제하고 올바른 대표자가 다시 신청하게 하세요. 가입 신청만으로 실제 대표자 신원이 인증되는 것은 아닙니다.

## 3. 일반 동아리 대표자 사용 순서

1. 일반 동아리 사용자 → 회원가입에서 등록된 소속 동아리를 선택하고 계정을 신청합니다.
2. 가입 직후에는 **임시 회원(승인 대기)**입니다. 로그인해서 승인 상태는 확인할 수 있지만 예약·조회·취소는 할 수 없습니다.
3. 관리자 승인 후 다시 로그인합니다. 날짜 → 심정실·진리실·창의실 → 연속된 시간대를 선택합니다.
4. 동아리 이름은 로그인한 계정으로 자동 입력되어 변경할 수 없습니다. 대표자 이름·연락처·메모·동의 항목을 입력하고 예약합니다.
5. **우리 동아리 예약**에서 기존 예약까지 조회·취소합니다. 1.3.2부터 사용자 화면의 확인서 다운로드·예약코드·예약번호 표시는 제거했습니다. 사용이 시작된 예약은 관리자에게 취소를 요청합니다.
6. **계정 변경**에서 현재 비밀번호를 확인한 뒤 아이디 또는 비밀번호를 변경합니다. 저장하면 로그아웃되므로 새 정보로 다시 로그인합니다. 동아리 이름과 방 정보는 관리자가 변경합니다.

## 4. 동시 로그인과 장소대여 권한

1.5.0부터 같은 동아리 계정으로 여러 기기에서 함께 로그인할 수 있습니다. 내 동아리 관리·벌점·다음 일정은 함께 확인하고, 장소대여 메뉴만 먼저 로그인한 한 접속에 허용합니다. 다른 접속자에게는 “장소 대여 메뉴는 한 명만 입장 가능합니다.” 팝업이 표시됩니다. 직접 주소나 API로 예약·예약 목록·취소·확인서 조회를 요청해도 서버에서 거절합니다.

로그아웃은 해당 브라우저의 접속과 장소대여 권한만 종료합니다. 먼저 로그인한 남은 활성 접속자가 다음 확인에서 권한을 이어받습니다. 화면이 보이는 동안 60초 간격으로 접속을 확인합니다. 창 종료·통신 단절·모바일 백그라운드 등으로 확인이 끊기면 마지막 확인 후 약 3분에 권한이 만료됩니다. 다른 활성 접속자의 다음 확인에서 인계하므로 자동 확인으로는 최대 약 1분이 더 걸릴 수 있습니다. ‘이용 권한 다시 확인’이나 메뉴 클릭으로 즉시 다시 확인할 수 있습니다. 기존 담당자가 다시 접속해도 새 담당자의 권한을 빼앗지 않습니다.

같은 브라우저의 여러 탭은 하나의 쿠키를 공유하여 **하나의 로그인**입니다. 비밀번호 전달이나 같은 브라우저의 탭을 하나로 제한하는 기능은 아닙니다. 계정 정보 수정·정지·삭제·동아리 비활성화는 해당 동아리의 전체 접속을 종료합니다. 로그인 유효기간은 최대 8시간입니다.

세부 사용·적용 방법은 RENTAL_ACCESS_UPDATE.md를 참고하세요.

## 5. 보안과 비밀번호 표시

요구한 관리자 비밀번호 조회를 지원하려면 비밀번호를 복원 가능한 형태로도 보관해야 합니다. 이 버전은 로그인 검증용 해시(별도 서버 비밀값을 결합한 PBKDF2)와 조회용 AES-GCM 암호문을 분리해 저장합니다. 계정 암호화 키는 기존 방 암호화 키에서 목적을 구분해 파생하며, 키는 DB나 화면 번들에 넣지 않습니다.

이는 해시만 저장하는 방식보다 **관리자 계정과 서버 키 보호가 더 중요한 설계**입니다. 요구한 조회 기능을 구현한 데 따른 차이입니다. 개인 이메일·학교 포털 등 다른 서비스와 같은 비밀번호를 쓰지 않도록 가입 화면에도 안내했습니다. 관리자 비밀번호는 운영 담당자만 알고 있어야 합니다. 관리자 비밀번호 변경 시 모든 관리자 세션을 종료합니다.

계정·방 비밀번호는 목록 응답에 포함하지 않습니다. 별도 요청에서만 표시하고 캐시를 금지합니다. 계정 비밀번호는 관리자 재확인과 조회 기록을 거치고, 화면에서는 30초 후 또는 탭을 숨기면 다시 가립니다. 조회된 비밀번호의 캡처·복사·타인 공유까지 기술적으로 막지는 못합니다.

HttpOnly·Secure·SameSite 쿠키, 서버에서 소속/승인 상태 확인, POST 출처 검사, 요청 크기 제한, SQL 매개변수, 로그인·가입 시도 제한, 원자적 계정/예약 변경을 적용했습니다. 세션 무효화는 예약·취소 저장 시점에도 다시 확인합니다. 모든 오류나 모든 공격의 부재를 보장하는 의미는 아닙니다.

## 6. 적용 후 PC·모바일에서 확인

- 관리자 계정 유지, 기존 동아리·예약·벌점 유지
- 대표자 가입 → 임시 회원 예약 차단 → 관리자 승인 → 다시 로그인
- 동아리 이름 자동 입력, 날짜·장소·시간 선택과 예약·우리 동아리 예약 조회 및 취소
- 우리 동아리 예약 조회·취소, 다른 동아리 예약 접근 차단
- PC 로그인 후 모바일에서 같은 계정 로그인 → PC의 다음 요청 차단
- 아이디·비밀번호 변경, 관리자 초기화·정지·삭제 후 접속 종료
- 관리자 계정·방 비밀번호 확인, 여러 날짜 오픈, 관리자 추가승인, 벌점 통계

이 수정본은 자동 검사, 타입 검사, 화면 빌드, 로컬 Workers/D1 검증을 수행합니다. 이 작업 환경에서는 운영 Cloudflare 계정에 접근할 수 없고 지원되는 브라우저 제어도 없어 실제 운영 사이트와 PC·모바일 브라우저의 클릭·화면 검증은 수행하지 못했습니다. 로컬 결과가 무료 서버의 CPU 제한이나 실제 부하를 보장하지는 않습니다. 상세 결과는 [REVIEW.md](../../07-todo-list/review-history/REVIEW.md)에 있습니다.
