# 1.9.1 사진 제출 통합·관리자 15분 업데이트

## 변경 내용

- 관리자 → 장소대여 시스템 관리 → 예약 목록의 입실·퇴실 버튼을 **사진 제출 / 사진 미제출 버튼 하나**로 통합했습니다.
- 버튼을 누르면 입실·퇴실 사진 상태를 한 번의 요청과 하나의 DB 트랜잭션으로 함께 변경합니다. 제출 상태를 다시 누르면 둘 다 미제출로 돌아갑니다. 저장 중에는 중복 클릭을 막습니다.
- 기존에 입실 또는 퇴실만 확인된 예약은 기록을 그대로 두고, 버튼 아래에 어느 쪽만 확인되었는지 표시합니다. 관리자가 버튼을 누를 때부터 두 상태를 함께 변경합니다.
- 사진 상태를 바꾸어도 예약 내용·예약 상태·기존 벌점은 바뀌지 않습니다. 사진 미제출 벌점은 기존처럼 별도의 관리자 작업이며, 제출 처리로 기존 벌점을 자동 취소하지 않습니다. 취소·삭제된 예약의 사진 버튼은 사용할 수 없습니다.
- 관리자 로그인은 **15분 미사용 시 만료**됩니다. 마지막 관리자 조작 이후 15분이며, 자동 조회나 시계 표시만으로는 연장되지 않습니다. 서버 권한 검사·화면 안내·다른 탭의 활동 반영에 같은 기준을 사용합니다.
- 관리자 2차 인증, 계정 수정 시 재인증, 최대 8시간 로그인 제한은 유지합니다. 동아리 대표 계정의 접속 정책은 동일합니다.

## 기존 데이터 보존

1.9.0에서 이번 업데이트를 적용하면 새 DB 마이그레이션이 없습니다. 기존 예약·사진 확인 상태·동아리·계정·벌점·한국시간 자동 오픈 설정을 초기화하지 않습니다. 사진을 한쪽만 확인했던 기존 예약도 일괄 변경하지 않습니다. 더 이전 버전에서 적용하면 누적 업데이트에 필요한 이전 마이그레이션과 보안 전환이 함께 진행됩니다.

## 적용 순서

1. ZIP을 기존 배포 폴더와 **다른 새 폴더**에 압축 해제합니다.
2. 새 폴더에서 **APPLY_SITE_UPDATE.cmd**를 실행합니다.
3. 실제로 사용 중인 `wrangler.json`, `.secrets/runtime.json`, `node_modules`가 있는 기존 배포 폴더의 경로를 붙여넣고 Enter를 누릅니다.
4. 안내에 따라 DB 백업 암호와 키 보관용 암호를 서로 다르게 입력합니다. 도구가 먼저 기존 DB를 암호화 백업하고 소스를 보관한 다음, 같은 DB·같은 Worker에 배포합니다. 기존 보안 키와 공개/비공개 설정을 유지합니다. 백업 실패 시 파일 교체와 DB 변경 전에 중단합니다.
5. 완료 후 운영 사이트를 새로고침하고 관리자 → 장소대여 시스템 관리 → 예약 목록에서 사진 버튼을 확인합니다. 이전 화면이 계속 나오면 Ctrl+F5로 다시 불러오세요. 새 정책을 확인하려면 관리자 로그아웃 후 2차 인증으로 다시 로그인합니다.

신규 서버 준비나 DB 생성 명령은 다시 실행하지 않습니다. 상세 검사 범위는 REVIEW.md에 있습니다. 이 파일 제공만으로 실제 운영 서버가 변경되지는 않습니다.
